# Observed provider saved-session JSONL

Chronos v0.1 reads two exact, locally observed saved-session formats. These are implementation observations, not public provider contracts or claims of broader compatibility. Fixtures are synthetic and sanitized; all transcript text, credentials, IDs, and path values in them are fictional, and encrypted reasoning is represented only by an inert placeholder.

| Format   | Accepted source version                              | Observed provenance                                  |
| -------- | ---------------------------------------------------- | ---------------------------------------------------- |
| `codex`  | `session_meta.payload.cli_version = 0.146.0-alpha.3` | `~/.codex/sessions/YYYY/MM/DD/rollout-...UUID.jsonl` |
| `claude` | every root record has `version = 2.1.225`            | `~/.claude/projects/<encoded-project>/<uuid>.jsonl`  |

Use `chronos import FILE --format codex` or `--format claude`. Missing and unknown versions fail the entire import. `--format chronos` reads Chronos's documented format and remains the default for backward compatibility.

Codex normalizes `event_msg.user_message`, assistant `response_item.message` text, function/custom tool calls and outputs, and explicit errors/system messages. The duplicate `event_msg.agent_message` surface is ignored. Reasoning, encrypted content, world state, turn context, token accounting, and settings are omitted.

Claude normalizes string user instructions, assistant text/tool-use blocks, user tool-result blocks, and explicit system/errors. Thinking/signatures, file-history snapshots and deltas, titles, colors, modes, and permission metadata are omitted. File order and resolved `parentUuid` links must describe one linear root history. Sidechains, unresolved parents, and nonlinear roots fail rather than being represented as invented branches.

Provider imports emit diagnostics for unknown record kinds. They never perform I/O or execute recorded tools. Canonical redaction remains best-effort and is not a security boundary. Raw retention is rejected in v0.1 because the encrypted restricted raw store does not exist yet.

## Live recording

`chronos record --agent codex|claude --workspace PATH --instruction-file FILE` first checks the installed CLI's exact version with `codex --version` or `claude --version`. It then uses the locally observed noninteractive commands:

- `codex exec -C PATH --json -- FIXED_PROMPT`
- `claude --print --output-format stream-json --verbose -- FIXED_PROMPT`

The fixed prompt names a unique, mode-restricted file under the workspace's excluded `.chronos/` directory; user instruction text is never placed in an argument. Processes use an argument array with `shell: false`.

The Codex stream subset accepts exactly one ordered `thread.started`, `turn.started`, and terminal `turn.completed` or `turn.failed`, with completed agent messages, hidden reasoning frames, and started/completed command, MCP, or `file_change` tool items inside the turn. A successful terminal requires the pinned integer usage fields; a failed terminal requires an error message. Started/completed identity and stable metadata must agree. A completed `command_execution` requires string `aggregated_output` and an integer `exit_code`; completion-only command records synthesize the matching call and result as one normalized batch. The Claude subset accepts one `system.init`, exactly one terminal `result`, assistant text/tool-use blocks, inert thinking blocks, inert echoed user text, and matching user tool-result blocks. A success result requires `subtype: success`, `is_error: false`, and result text; pinned failure subtypes require `is_error: true` and failure text. Every later Claude record is bound to that initialization's `session_id`; assistant and user envelopes require unique top-level `uuid` values, their `message.role` must match the envelope, assistant `message.id` values are required and unique, and `is_error` is boolean when present. Call IDs are unique and complete once. Missing, repeated, malformed, or followed terminal records fail closed, and a provider-declared failure settles the branch failed. Any other record or content-block type also fails closed because a new provider surface may mutate the workspace; Chronos marks that workspace state unknown even when no recognized tool call preceded it. Streams are bounded by record, line, and total byte limits; the process is terminated immediately on malformed initialization, invalid timestamps, repeated identities, unmatched or repeated results, unfinished tool calls, an oversized unterminated line, or cancellation. Chronos accepts exactly the single raw version line observed for each supported executable, including no blank or surrounding-whitespace frames, before it creates Chronos home, instruction, or baseline artifacts. The executable is resolved once from `PATH` to an absolute canonical regular file and its filesystem identity is checked immediately around both the probe and recording spawn; Windows accepts native `.exe`/`.com` files, not shell scripts. The separate check is necessary because the observed Codex stream initialization does not carry a CLI version.

Instruction files are read through one bounded descriptor. POSIX uses `O_NOFOLLOW` plus before/after `fstat`; Windows repeats lstat, canonical-path, and file-identity checks. Regular-file type, 1 MiB size, stable identity/size/mtime, exact byte count, and fatal UTF-8 decoding are required. Windows has no Node primitive equivalent to `openat` with a no-reparse guarantee, so a hostile reparse swap inside the remaining check/open window is a documented residual risk.

Chronos takes one snapshot at the end of each provider record that completes one or more tool results. The record's complete normalized batch and its filesystem-change checkpoint land in one database transaction; capture failure instead lands the complete batch plus a safe dirty error, and transaction failure lands none of the batch. Snapshot files are read from one POSIX `O_NOFOLLOW` descriptor with stable identity/metadata and canonical containment checks. Windows rejects detected symlink/reparse aliases and repeats canonical containment and identity checks before and after reading the same descriptor; Node exposes no Windows no-reparse/open-at primitive, so a hostile privileged reparse swap is a documented residual. Content-store/workspace comparisons use canonical roots and case-insensitive Windows containment. This does not freeze the provider process or detect another process writing the workspace concurrently, so exclusions and the concurrent-writer limitation are reported rather than hidden. POSIX permission tightening is applied where supported; on Windows, filesystem ACLs remain authoritative.
